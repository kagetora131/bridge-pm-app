# ブリッジPM (Bridge PM)

海外オフショア開発チームと日本側の橋渡し役（ブリッジSE／PM）向けの、多言語・タイムゾーン対応プロジェクト管理アプリの MVP です。詳細な企画意図は [CLAUDE.md](./CLAUDE.md) を参照してください。

## 実装済み機能（MVP）

- **プロジェクト管理**: プロジェクト(名前・ジャンル・ステータス・現在フェーズ・開始日/リリース目標日)を登録し、メンバーのアサイン(役割・週間配分時間)を紐付け。プロジェクトに紐づくタスクの件数・完了数も表示。
- **要員の稼働配分・過負荷判定**: メンバーごとの週間稼働上限(`weeklyCapacityHours`)と、全プロジェクトへのアサイン時間の合計をつき合わせ、上限を超えたメンバーには「過負荷」バッジを表示。値はプロジェクト側のアサインから毎回再計算するため、上限や配分を変更しても手動で同期する必要はない。
- **予算超過リスクの可視化・スケジュール延長コストシミュレーション**: プロジェクトごとに「週次バーンレート」(アサインされた各メンバーの時間単価USD×配分時間の合計)を算出し、①現時点までの消化額(開始日からの経過週数×バーンレート)②現在の人員配置のまま完走した場合の総コスト予測(開始日〜リリース目標日の全期間×バーンレート)を表示。予測が予算総額を超える場合はプロジェクト一覧に「予算超過リスクあり」バッジを表示。延長日数を入力すると、週次バーンレート÷5で算出した「1営業日あたりの追加コスト」×延長日数で概算追加コストをその場でシミュレーションできる。すべて「現在の人員配置が変わらない」という単純化前提の目安値である旨をUI上に明記。通貨計算はUSDに統一し、メンバーには参考情報として現地通貨での単価も任意で保持できる(計算には使用しない)。
- **タスクはメンバー起点で管理**: 独立したタスク一覧タブは廃止し、各メンバーのカードに「担当タスク」として表示・追加・編集する構成にした(「◯◯さんが何をいつまでやっているか」を見る単位として、タスク単体の一覧より意味がある、というフィードバックを反映)。タイトル(日英)・所属プロジェクト・開始日・期限・ステータス(未着手/進行中/ブロック中/完了)・依存タスクを管理でき、依存タスクが未完了のまま残っている場合は警告表示。
- **カレンダー(中心画面・月表示)**: プロジェクト・メンバーで絞り込んだ上で、タスクが稼働している各日に「進捗ペース%」を表示する(例: 5日間のタスクなら1日目20%→3日目60%…と、経過日数に応じて日ごとに増えていく)。「アートさんの作業はいつからいつまで、どれくらい進んでいるか」を月表示のまま一目で追えるようにする狙い。タスクの左端はプロジェクトごとに色分け(プロジェクトIDから決定的に色を割り当てるため、他のプロジェクトを追加/削除しても既存の色は変わらない)し、上部に凡例を表示。「誰がどのプロジェクトの作業をしているか」を色だけでも把握できる。%はあくまで経過日数から算出した目安ペースで、実績入力に基づくものではない旨をUI上に明記(ブロック中のタスクは%の代わりに状態を表示)。前月・翌月・今日への移動に加え、月ジャンプのプルダウンで数ヶ月先まで一気に移動可能。
- **メンバー管理**: 氏名・役割・拠点・タイムゾーン・稼働時間帯（現地時間）・**稼働曜日**・使用言語を登録し、各メンバーの現在時刻をリアルタイム表示。稼働曜日を持たせているのは、拠点によって週末が異なるケース(例: ドバイは金・土が休みで日曜が稼働日)に対応するため。メンバー自身のタイムゾーン欄は主要都市~30件の絞り込みリストから選択(新規拠点の追加にも対応できる広さ)。一方、会議関連の「表示タイムゾーン」「基準タイムゾーン」は、実際に在籍しているメンバーの拠点(+閲覧者自身のタイムゾーン)だけを候補にするため、チーム構成に応じて自動的に絞り込まれる。
- **会議時間帯の自動提案（差別化のコア機能）**: 参加メンバーを選ぶと、全員のタイムゾーン**および稼働曜日**を考慮した稼働時間の重なりを計算。重なりがなければ「もっとも負担が少ない妥協案」（どのメンバーが何分残業/早出になるか）を提示。各メンバーの稼働時間帯を横棒タイムラインで可視化し、その日が稼働日でないメンバーには「稼働日ではありません」と表示。
- **定例会議(週表示カレンダー)**: 毎週同じ曜日・時刻に行う会議(タイトル・参加者・所要時間・基準タイムゾーン・曜日+時刻・開始/終了日)を登録できる。ほぼ毎日/毎週やり取りが発生する部門向けに、単発の時間提案とは別に「決まったスロットを繰り返し登録する」導線を用意。登録した会議は、時間軸つきの週間カレンダー(0-23時×7日)に表示され、表示タイムゾーンを切り替えると各会議が実際に何曜日の何時になるかを正しく再計算する(例: ロサンゼルス火曜9時の会議はJST表示だと水曜1時になる)。
- **技術用語集**: 日英対訳＋メモを登録・検索。
- **多言語UI切り替え**: ヘッダーのボタンで日本語⇔英語をワンクリック切り替え。

サンプルデータはゲーム開発スタジオを想定した架空のシナリオ([docs/bridge_pm_dummy_data.json](./docs/bridge_pm_dummy_data.json)、6拠点13名・過負荷2名・依存関係とブロック中タスクを含む)を元にしている。過負荷判定やドバイの稼働曜日は、このデータに付属する期待値と突き合わせて動作確認済み。「ネオトーキョー2088」プロジェクトには、アート制作→プログラム組み込み→翻訳(並行)→翻訳テキストの反映→QAという、ローカライズ作業の一連の流れが分かるタスク例を用意している。

### サンプルデータの自動更新について

開発中に頻繁にサンプルデータを更新するため、`src/lib/seedVersion.ts` のバージョン文字列をキーに、ブラウザに保存済みのデータと最新のサンプルデータが食い違っていれば**自動的に最新のサンプルデータへリセットする**仕組みを入れている(でないと、一度保存された古いデータがブラウザに残り続け、コード側でサンプルデータを更新しても画面に反映されない)。ヘッダー右上の「サンプルデータにリセット」ボタンからも手動でいつでもリセットできる。**実データを入力し始めたら、このバージョン文字列を固定するかリセット処理自体を無効化すること**(でないと入力したデータが不意に消える)。

## 今回のスコープ外（意図的に未実装）

- **タスク説明のAI自動翻訳**: CLAUDE.md の当初案は Claude API を利用する想定でしたが、従量課金が発生するため「完全無料」の方針に合わせて今回は見送りました。上記の通りタスクは日英を手入力する形にしています。将来的にAPIを追加する場合も、`Task` 型に `titleJa`/`titleEn` の2フィールドを既に持たせてあるため、片方を自動生成するロジックを後から差し込みやすい構造にしています。
- **Supabase等によるサーバー保存・認証**: 外部アカウント作成が必要なため今回は見送り、**ブラウザの localStorage** にのみ保存しています（サーバーへの送信は一切ありません）。複数端末・複数人での共有が必要になった段階で、Supabase等への移行を検討してください。

## セットアップ

```bash
npm install
npm run dev
```

`http://localhost:5173` で確認できます。初回起動時はデモ用のサンプルデータ（架空のメンバー・タスク・用語）が表示されます。編集・削除して実際のデータに置き換えてください。

## ビルド

```bash
npm run build
```

## データの扱いについて

すべてのデータはブラウザの localStorage にのみ保存され、外部サーバーへの送信は行われません。ブラウザのデータを削除するとタスク・メンバー・用語集の情報も失われる点に注意してください（バックアップ機能は今後の課題）。
